# 本机短链跳转压测（2026-10-19）

本报告记录当前单库主版本在开发机上的一次实测。它证明本次配置和数据下达到过的负载，不代表生产容量上限；不可与历史架构或共享云主机数据直接比较。

## 环境与口径

| 项目 | 设置 |
|---|---|
| 代码基线 | `4b6a9d5`；压测时包含工作区未提交改动，见下方说明 |
| 机器 | AMD Ryzen 7 7840HS，8 核 / 16 逻辑处理器，Windows 11，15.2 GiB RAM |
| 运行时 | Java 21.0.8，Spring Boot 4.0.7，MySQL 8.4.11，Redis 7.2.4，RabbitMQ 4.3.4 |
| 数据 | 独立 MySQL 测试库，100,000 条短链；Zipf α=1.0，seed=20261019，固定 200,000 条请求序列 |
| 被测链路 | 本机 HTTP `127.0.0.1` 跳转，不跟随 302；检查 Location 指向种子 URL |
| 负载模型 | 闭环固定并发；每档 30 秒，1 / 4 / 8 / 16 / 32 / 64 VU；超出档位时停止条件为非 302 或单档 P95 > 250 ms |
| 缓存 | 对比 Redis L2 与 Caffeine L1 + Redis L2；L1 最大 10,000 项 |
| 隔离 | MySQL 使用新建测试库，Redis 仅监听临时回环端口，RabbitMQ 使用专属 vhost；共享主机数据未用于测试 |

应用、中间件与发压程序运行在同一台开发机。主吞吐测试关闭统计采集，以便单独观察跳转读路径；因此主吞吐数字不包含 RabbitMQ 统计开销，也不是公网 HTTPS 结果。完整异步统计另做了独立对账。

主吞吐应用参数：JVM `-Xms256m -Xmx1g`、HTTP 端口 `18080`、Hikari 最大连接池 `32`、跳转限流关闭、统计关闭、数据库回源预算 `5000 QPS / 32 并发`。Redis 使用全新临时实例；仅 L2 阶段设 `l1-enabled=false`，完整缓存阶段设 `l1-enabled=true`，两个阶段都设 `l2-enabled=true`。

压测时 HEAD 为 `4b6a9d5`。工作区还含未提交的 `StatsCollector` RabbitMQ 确认方法兼容修正、`StatsConsumer` import 排序，以及已有的 `RedirectController` 工作区改动；Maven 构建使用这些当前文件。提交前应重新核对这些改动属于谁。

## 缓存阶段结果

每项为 RPS / P95 / P99（毫秒）。各阶段返回均为 302，错误数为 0。

| 并发 VU | 仅 Redis L2 | Caffeine L1 + Redis L2 |
|---:|---:|---:|
| 1 | 250 / 9.24 / 15.95 | 257 / 9.52 / 16.01 |
| 4 | 1,742 / 6.64 / 7.45 | 2,065 / 6.57 / 7.36 |
| 8 | 3,778 / 7.44 / 8.41 | 4,439 / 7.22 / 8.28 |
| 16 | 4,834 / 4.50 / 10.64 | 5,038 / 4.21 / 8.69 |
| 32 | 4,847 / 7.70 / 12.27 | 4,996 / 7.63 / 11.14 |
| 64 | 4,750 / 14.96 / 25.45 | 4,901 / 14.90 / 22.14 |

单进程 Node 发压器本身约占满一个逻辑核，单进程 64 VU 的一次热缓存复测达到 5,885 RPS、P95 14.71 ms、P99 20.48 ms。为减少发压端瓶颈，使用多个独立发压进程交叉验证：

| 独立发压进程 × 每进程 VU | 总并发 | 总请求数 | 实测 RPS | P50 / P95 / P99（ms） | 状态码 |
|---:|---:|---:|---:|---:|---|
| 4 × 64 | 256 | 581,122 | 18,675 | 12.96 / 16.11 / 26.54 | 302：100% |
| 6 × 64 | 384 | 743,142 | 23,656 | 15.03 / 19.05 / 31.18 | 302：100% |

多进程阶段仍在同一台开发机上运行。6 进程阶段每个发压进程约使用 95% 的一个逻辑核（合计约 5.7 核）；采样到系统 CPU 约 50%、Java 进程 CPU 约 22%、Java 工作集约 577 MiB、可用内存约 6.7 GiB。发压端和服务共享 CPU，故 23,656 RPS 是本配置下的观测值，不是服务极限。

## 异步统计对账

在 L1 + L2、启用 RabbitMQ 统计消费者的独立 30 秒单并发验证中：

- 请求 6,670 次，返回 302 共 6,670 次。
- 数据库日汇总 PV 为 6,670，与成功跳转数一致。
- 统计 pending、dropped、publishFailures 均为 0，RabbitMQ 统计队列深度为 0。
- `flushedRows=6,444` 是落库行数，不等同于事件数；同一短码的小时与日汇总使用不同记录。

## 可复现性与限制

运行器为仓库内的 `benchmark/local-redirect.mjs`，多进程编排器为 `benchmark/local-redirect-fanout.mjs`。它们只依赖 Node.js 内置 HTTP 模块，并限制目标为 loopback、每档最长 120 秒、最多 8 个发压进程且每进程最多 64 VU。复跑时先建独立测试库并导入 `sql/schema.sql`；将 `benchmark/seed.sql` 复制为测试副本，仅在副本里把 `USE shortlink;` 改为测试库名、把 `@total_rows` 改为 100000，再执行副本。原种子脚本含 `TRUNCATE t_link`，不可直接对开发或业务库运行。请求日志可用以下命令重新生成：

```powershell
python benchmark/gen_requests.py --rows 100000 --requests 200000 --alpha 1.0 --seed 20261019 -o .local/loadtest/requests.txt
$env:BASE_URL = 'http://127.0.0.1:18080'
$env:REQ_FILE = '.local/loadtest/requests.txt'
$env:CLIENTS = '6'
$env:VUS_PER_CLIENT = '64'
$env:STAGE_SECONDS = '30'
node benchmark/local-redirect-fanout.mjs
```

多进程的每个子进程会输出单独结果；设 `RESULT_DIR` 可以指定保存位置。比较缓存阶段前应分别重启/清空专用 Redis，并重启应用以清空 L1，不能对共享 Redis 使用 `FLUSHALL`。

本次 Maven `-DskipTests package` 构建成功；跳转运行器和多进程编排器通过 `node --check`。本次不是服务容量上限测试：本机闭环负载、热缓存、未计入统计的主吞吐阶段、HTTP 回环链路、有限数据集都会影响结果。不要把“23.7k RPS”写成可承诺的生产 QPS；简历中应连同机器、100k 数据、Zipf 分布、384 VU、缓存配置和本机同机限制一起说明。
