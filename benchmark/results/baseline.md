常见的三个，看看你有没有中：

1. **同步日志刷盘** —— Logback 默认同步 + 每次跳转打一行 INFO。改 `AsyncAppender`，常见 +15~30%

## 最终写进简历的句子（从上面的表里摘）

```
Zipf(α=___) 分布压测下，4C8G 单机跳转 QPS 从 ___ (裸 MySQL) 提升至 ___，
P99 从 ___ms 降至 ___ms，L1 本地缓存命中率 ___%（整体缓存命中率 ___%）；
用 async-profiler 定位到 ___ 瓶颈，改 ___ 后再提升 ___%。
```

**三个必守的点**：

1. 标明分布和 α —— 这是"真压过"的签名
2. 区分 **L1 命中率** 和 **整体命中率**（后者含 Redis L2，稳态下 99.9%+）
3. 数字宁小勿夸。"支撑百万 QPS"一问就穿；"1.1k → 3.8w，P99 86ms → 4ms"可信度高一百倍
